# FM27Real 方案

> 状态：方案已批准（2026-11-21）。阶段 0、1 完成。协议细节见 [PROTOCOL.md](PROTOCOL.md)。本项目从零设计，不复用 FMTalking 的代码或设计。

## 目标

不只是「能和球员聊天」，而是把主教练的完整生活还原出来：人际关系、媒体、社交网络、博彩市场、个人合同和职业生涯。
每件事都有因果：你说的话被记住，影响关系、舆论、赔率和董事会信任，反过来又改变游戏里的数值和剧情。

## 架构

```
┌──────────────── FM27（游戏进程）────────────────┐
│  libfm27real.dylib（Steam 启动选项注入）          │
│  · 通过 il2cpp 接口按「类名/字段名」读写游戏对象    │
│  · 本机回环接口 127.0.0.1 + 随机令牌               │
└───────────────────────┬─────────────────────────┘
                        │ 比赛结果 / 阵容 / 日期推进 / 写回指令
┌───────────────────────┴─────────────────────────┐
│  FM27Real App（Mac 原生，SwiftUI）                │
│                                                 │
│  世界引擎（确定性，决定「发生了什么」）             │
│  · 每个存档一个 SQLite：人物、关系、记忆、舆论、     │
│    赔率、事件时间线                               │
│  · 按游戏日期推进；所有数值变化由引擎规则计算       │
│                                                 │
│  模型 API 层（只负责「怎么说」）                    │
│  · 统一接口：输入世界状态 + 人物，输出文字和结构化意图 │
│  · 引擎校验意图后才生效，模型不能直接改数值          │
│  · 可换后端；开发测试阶段用 Claude                  │
└─────────────────────────────────────────────────┘
```

**世界引擎和模型分开：** 引擎决定后果（士气 -5、赔率变化、董事会警告），模型只负责把人写活。这样同样的事件结果可复现，换模型也不会改变游戏规则。

**模型 API 层：** 一个 provider 接口，接口后面可以是任意后端。测试期间用 Claude：
- 默认走本账号（本机 Claude Code 命令行无界面调用，关闭所有工具），不需要 API key；
- 之后可加 Anthropic API（官方 SDK）和其他兼容后端，在设置里切换。

**为什么体验放在 App 里：** 游戏内界面（UI Toolkit）最难改，也最容易随更新坏掉。游戏里只留最小的读写桥，体验放在 App。系统成熟后再考虑在游戏里加入口。

## App 界面

整体像主教练的手机，深色风格，与 FM 观感一致。

- **头像和队徽直接用 FM 自己的图：**
  - 球员/职员头像：`graphics/faces/face_<UID>.png`、小图 `graphics/iconfaces/iconface_<UID>.png`；
  - 俱乐部队徽：`graphics/` 下的 logo 包（按包内 `config.xml` 映射到俱乐部 UID）；
  - 球衣：`graphics/pictures/kits`；
  - 用桥从游戏读出每个人的 UID 来匹配；没有图片时显示带俱乐部配色的首字母头像。
  - 以后可以让桥直接导出游戏内置头像，覆盖没装头像包的玩家。
- **页面：** 消息（私聊）、发布会、社交动态、博彩、我的职业、时间线。
- 社交动态像真实的 App：头像、认证标记、转发/点赞数、热搜、截图被疯传。

## 功能系统

| 系统 | 体验 | 写回游戏 |
| --- | --- | --- |
| 人际关系 | 球员、教练组、董事会、经纪人各有性格和长期记忆；私聊、承诺、冲突都会被记住，关系会累积也会破裂 | 士气、幸福度、对主教练的看法（逐项验证后开启） |
| 新闻发布会 | 赛前/赛后发布会，记者有立场和风格，问题来自真实比赛数据（伤病、争议判罚、换人）；回答会被断章取义 | 球员士气、董事会和球迷信心 |
| 社交媒体（可互动） | 球迷、记者、球员、对手的动态流；热搜、梗、带节奏。你能**回复、私信、发帖、和球迷对线**。球迷会骂你的首发、换人、转会和发布会发言；每个账号有性格和记忆（死忠、黑子、数据党、对手球迷、八卦号）。吵架会出圈：截图疯传、记者跟进、球员点赞或拉黑你、足协因不当言论罚款、董事会警告 | 舆论值、董事会信心；罚款等后果验证后写回 |
| 博彩市场 | 虚拟博彩公司按球队实力、状态、伤病开赔率（Elo + 泊松模型）：单场、夺冠、降级、「下一个下课的主教练」 | 不写回；作为舆论和压力信号。纯游戏内虚拟，不涉及真钱 |
| 主教练职业 | 你自己的合同、奖金条款、经纪人、其他俱乐部来挖人、下课压力 | 视可行性写回合同相关数据 |

## 分阶段

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 0 注入桥 ✅ | 启动器 `scripts/launch.sh` 注入；等运行时启动后导出类/字段清单（144 个程序集、20,102 个类） | 游戏正常运行，清单完整（2026-11-21 完成） |
| 1 读数据 ✅ | 数据通道监听、属性目录、主动查询；本机查询接口（127.0.0.1，令牌）；`tools/fm27.py` 输出阵容 JSON（姓名、年龄、位置、国籍、性格、简介、头像） | 31 人阵容带 30 张 FM 头像（2026-11-21）；能力值、日期、比赛结果留到阶段 2 按需补 |
| 2 游戏内面板 + 世界引擎 + 模型 API（进行中，见 [PHASE2.md](PHASE2.md)） | 游戏窗口内网页面板、Python 世界引擎（SQLite、存档绑定）、模型接口和 Claude 测试后端、人物私聊和长期记忆 | 和一名球员聊天，第二天他还记得 |
| 3 人脉、发布会、社交媒体（见 [PHASE3.md](PHASE3.md)） | 主动联系你的人（球员、教练组、高层、对手、经纪人、旧识、记者）、故事引擎、新闻发布会、社交媒体、点击跳转 | 每天有人因为真事找你；发布会上记者按真实状况刁难你 |
| 4 博彩与职业 | 赔率模型、主教练合同、下课压力、工作邀请 | 赔率随比赛变化 |
| 5 写回游戏 | 逐项验证写回士气、幸福度等，全部在存档副本上测试 | 改动在游戏里可见，存档读回仍正确 |

## 需要你配合的
1. 在终端登录 Claude 命令行一次（测试后端用）。
2. 用 `scripts/launch.sh` 启动游戏（Steam 需先打开）。
3. 测试时用一个生涯副本，不要用主存档。
4. 每次验证需要从 Steam 启动游戏并进入生涯。

## 风险
- FM 更新可能改类名或字段，需要跟进；按名字查找比固定偏移更耐更新。
- 写回游戏数据可能损坏存档，所以阶段 5 之前只读不写。
- 测试期间 AI 对话会消耗你 Claude 账号的用量额度。

## 阶段 0 的发现（给阶段 1）

- FM 的游戏数据库和模拟在原生 C++ 引擎里，C# 层（`FM.UI`、`SI.Bindable` 等）主要是界面和画面。
- 两边通过 `FM.GamePlugin` 通信：`IGamePlugin`、`IPluginDataReceiver`、`ChannelData`/`ChannelAction`、`UiRecordID`、`GameRecordSerialisation`。界面按记录 ID 绑定数据。
- 所以阶段 1 的方向是：监听或调用这些数据通道，按记录 ID 取球员、俱乐部、日期，而不是在 C# 对象里找字段。
