> 状态：待批准（2026-11-21）。数据来自对 FM27 代码和一个真实生涯（莱斯特城，2028-03-07）的实测。

## 二、设计

原则和阶段 2 一致：**世界引擎决定发生什么，Claude 只负责把话说出来。**

### 1. 社交网络（每个游戏日从 FM 刷新）

- 节点：一线队球员和主要职员。
- 连线：同一社交圈、偏爱关系（兄弟 > 好友/队友 > 前队友）、地位（领袖说话传得远）。
- 加上我们自己的数据：每个球员对你的信任/好感/尊重（阶段 2 的关系分）、他记得的对话。

### 2. 话题从哪来（只用真实发生的事）

- FM 的状态：幸福度顾虑（「对队内处境心存顾虑」）、不开心的球员、上场时间、伤病、合同、转会传闻、新援、比赛结果。
- 你的行为：私聊里说的话、做的承诺、（阶段 3 起）发布会和社交媒体发言。
- 变化：某人连续被放上替补、某人在训练里被批评、某人刚续约。

### 3. 传播（引擎规则，可复现）

每个游戏日，每条话题沿社交网络扩散：

- 好友、兄弟、同圈子：大概率传到；
- 球队领袖知道后会传遍自己的圈子；
- 圈外的人（例如那 3 个独行者）很少听到，也很少传；
- 每多传一手，内容可能走样（引擎记「准确度」，例如「教练可能卖萨姆」变成「教练已经决定卖萨姆」）；
- 每个球员记住「从谁那儿听到了什么」。

### 4. 你在游戏里看到什么

- **私聊会带上他听到的东西。** 他只知道传到他耳朵里的事：「听说你跟萨姆说他下个月会多打几场？」——前提是这话真的传到了他那儿。
- **更衣室动态**（面板里的新页面）：短场景，例如训练后几个人的闲聊、小圈子的群聊片段、更衣室里的争执。以「助理教练/队长透露」或「你无意间听到」的方式出现，保持真实感。
- **助理教练简报**：「苏塔那几个人对轮换有些想法」「塞特福德好像担心自己的位置」。

### 5. 后果

- 话题会改变我们自己的关系分：例如你对一个人的承诺没兑现，他的好友对你的信任也下降。
- 小圈子有共同情绪：领袖不满时，整个圈子对你的看法会往下走。
- 写回 FM（士气、幸福度）仍在阶段 5，优先用 FM 自己的动作（开队会、赞扬、和不开心的球员谈话），而不是直接改内存。

## 三、放进计划的位置

阶段 2 的私聊直接用上社交数据（成本低、效果大），八卦传播和更衣室动态在私聊打通后紧接着做：

| 步 | 内容 |
| --- | --- |
| 2c | 世界引擎骨架：存档识别、SQLite、人物快照**含社交数据**（圈子、地位、好友、顾虑、对你的看法） |
| 2d | 模型层 + Claude：人物对话的上下文包括他的社交处境 |
| 2e | 聊天面板：**每个球员单独的聊天记录**（修正现在共用一份的问题） |
| 2f | 记忆和关系分 |
| 2g（新增） | 八卦传播：话题从真实状态生成，沿社交网络扩散；私聊里人物会提到他听到的事 |
| 2h（新增） | 更衣室动态和助理教练简报 |

## 四、风险

| 风险 | 应对 |
| --- | --- |
| 八卦太多变成噪音 | 每天话题数有上限，只挑真正有变化的事 |
| 模型编造没发生的事 | 话题和传播都由引擎决定，模型只写台词；台词里提到的事实来自引擎 |
| 某些社交字段在别的存档里含义不同 | 已在莱斯特城对照过；换存档时先跑 `dressing-room` 检查 |
